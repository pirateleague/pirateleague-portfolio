01

LagAudit

Paper plugin · Java 21 · measure before optimizing

Compiles · 9,325 B

The problem. "The server lags" usually ends in random optimization before anyone knows whether the cause is entities, chunks, tile entities, a plugin or the host.

What it does. /lagaudit scan samples TPS, counts loaded chunks, entities and tile entities, ranks the 15 heaviest chunks and writes a timestamped report. /lagaudit top gives the short version in-game.

  • Read-only: it changes nothing in the world
  • Report to plugins/LagAudit/reports/
  • Paper 1.21.4 API, no database

What is verified, and what is not
Verified: the project compiles against the Paper API and produces a loadable jar. Not verified: behaviour on a live Paper server, because no server was available while building it. The plugin is deliberately read-only.
02

TicketDesk

Discord bot · discord.js 14 · SQLite

4 / 4 tests pass

The problem. Support requests disappear in DMs and general chat. Staff cannot see who owns a case, who else is allowed in, or what was already tried.

What it does. A panel button opens a private channel; the owner and staff can talk, add another person, and close with a reason. Every ticket is stored in SQLite with number, owner and status.

  • /ticket setup, /ticket add, /ticket close
  • Owner or Manage Server only
  • One open ticket per user, sequential numbers
test

✔ owner and staff can manage, strangers cannot
✔ close reasons are trimmed and capped
✔ store creates sequential tickets and closes them once

What is verified, and what is not
Verified: command handlers parse, the core store and permission rules are tested, and the bot exits with a clear message when no token is configured. Not verified: a live login to Discord, because no bot token was provided.
03

Invoice Reconciler

Python CLI · standard library · CSV in, Markdown out

10 / 10 tests pass

The problem. A small business exports bank lines and invoices, then checks them by hand. Underpayments, duplicate payments and unknown deposits are easy to miss.

What it does. Matches transactions on payment reference, with an amount/date/customer fallback. Flags paid, open, missing, underpaid, overpaid and duplicate invoices, plus unmatched bank lines.

  • One command, no cloud or subscription
  • Markdown report, non-zero exit code on exceptions
  • Works on a normal CSV export

07 / Straight answers

Questions worth asking.

No invented reviews, no borrowed screenshots. This is a small solo operation and the page says exactly what that means.

Are the projects on this page client work?
No. All three are self-built demos. They show how I structure, test and document code — they are not paid client projects, and there are no testimonials or client names on this page because there are none yet.
What if you can't fix my plugin?
Then you pay nothing for the fix. You still get a short written explanation of what is wrong and why it cannot be repaired within the agreed scope, so you can take it to another developer or replace the plugin.
Do you need my source code?
For a code fix, yes — a jar alone cannot be patched properly. For configuration or lag work I need the config, the spark report and the plugin list. If you only have the jar, I will tell you upfront what is and is not possible.
Which versions do you work with?
Paper 1.21.x is the main target, with Spigot and Purpur close behind. Older plugins can be migrated from 1.8–1.20, but I confirm feasibility before quoting. Bedrock/Geyser setups are fine as long as the plugin itself is Java-side.
Do I get the source code?
Yes. Every delivery includes the source, a README with build and install steps, and the tested jar. You own the delivered code for your server; I do not resell it.
Why are the prices lower than an agency?
Because this is one developer with no sales team, no account manager and no office. You get a fixed quote, direct replies and tested work — not a discovery call. If a job is worth more than the listed price, I will say so before starting.
