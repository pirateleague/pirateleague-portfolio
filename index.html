05Proof

Three demos, built and checked.

Not mockups and not client work. Each project is self-built, has source code and a check that actually ran — including what was not verified.

LagAudit

Compiles · 9,325 B

Paper plugin · Java 21 · read-only

The problem. "The server lags" usually ends in random optimisation before anyone knows whether the cause is entities, chunks, tile entities, a plugin or the host.

What it does. /lagaudit scan samples TPS, counts loaded chunks and entities, ranks the fifteen heaviest chunks and writes a timestamped report. It changes nothing in the world.

What is verified, and what is not

Verified: the project compiles against the Paper API and produces a loadable jar. Not verified: behaviour on a live Paper server, because none was available while building it.

TicketDesk

4 / 4 tests pass

Discord bot · discord.js 14 · SQLite

The problem. Support requests disappear in DMs and general chat. Staff cannot see who owns a case, who else is allowed in, or what was already tried.

What it does. A panel button opens a private channel; owner and staff can talk, add another person and close with a reason. Every ticket is stored in SQLite with number, owner and status.

What is verified, and what is not

Verified: command handlers parse, the core store and permission rules are tested, and the bot exits with a clear message when no token is configured. Not verified: a live login to Discord, because no token was provided.

Invoice Reconciler

10 / 10 tests pass

Python CLI · standard library · CSV in, report out

The problem. A small business exports bank lines and invoices, then checks them by hand. Underpayments, duplicate payments and unknown deposits are easy to miss.

What it does. Matches transactions on payment reference, with an amount/date/customer fallback. Flags paid, open, underpaid, overpaid and duplicate invoices, plus unmatched bank lines.

What is verified, and what is not

Verified: ten unit tests pass and the tool ran end-to-end on the included sample data. Not verified: a real bank export, which varies per bank.

07FAQ

Questions worth asking.

No invented reviews, no borrowed screenshots. This is a small solo operation and the page says exactly what that means.

What does the €5 bot actually include?
One clearly-scoped feature: a ticket panel, auto-roles, a welcome flow, a single slash command, or a small CSV script — delivered with the source, a README and one revision, either as a new small bot or added to one you already run. Not a multi-feature platform, not hosting, not a rebuild of an existing bot. If what you want needs more than that, I say so before starting and quote the real scope.
What if you can't fix it?
Then you pay nothing for the fix. You still get a short written explanation of what is wrong and why it cannot be repaired within the agreed scope, so you can take it to another developer or replace the plugin.
Do you need my source code?
For a code fix, yes — a jar alone cannot be patched properly. For configuration or lag work I need the config, the Spark report and the plugin list. If you only have the jar, I will tell you upfront what is and is not possible.
How do I pay you?
Litecoin for direct jobs, or BuiltByBit escrow if you prefer a middleman. Payment comes after you have tested the work. PayPal and SEPA are not available at the moment — if that is a hard requirement, say so in your first message and I will tell you honestly whether the job can go ahead.
Are the projects on this page client work?
No. All three are self-built demos. They show how I structure, test and document code — they are not paid client projects, and there are no testimonials or client names on this page because there are none yet.
Which versions do you work with?
Paper 1.21.x is the main target, with Spigot and Purpur close behind. Older plugins can be migrated from 1.8–1.20, but feasibility is confirmed before quoting. Bedrock/Geyser setups are fine as long as the plugin itself is Java-side.
